# 실시간 레이드 공급원 연결

`GET /api/raids/live`는 서버에 명시적으로 연결한 공급원의 관측만 반환합니다. 현재 연결된 공급원은 없으며, 기본 응답은 `status: "unconfigured"`, `raids: []`입니다. 일반 레이드 운영시간이나 이벤트 시간으로 체육관 레이드를 추정하지 않습니다.

## 서버 설정

서버 실행 환경에 `POKEDOKO_RAID_FEED_URL`(HTTPS)과 필요하면 `POKEDOKO_RAID_FEED_TOKEN`을 설정합니다. 토큰은 공급원 요청의 `Authorization: Bearer …` 헤더에만 들어갑니다. `NEXT_PUBLIC_` 접두사를 사용하거나 이 모듈을 클라이언트에 import하지 않습니다. URL과 토큰은 Git에 커밋하지 않습니다.

공급원은 개발자가 신뢰하며 데이터를 표시할 권한이 확인된 서비스여야 합니다. URL을 브라우저나 API 쿼리로 받지 않습니다. 서버는 HTTP, URL 내 계정 정보, 로컬 호스트·IP 주소를 거부하고 리디렉션을 따르지 않습니다. 임의 외부 주소를 사용자에게 입력받는 프록시로 확장하면 안 됩니다. 허용된 DNS 호스트의 관리도 운영자가 맡습니다.

## 공급원 응답 계약

최상위 JSON은 다음 구조입니다. 아래 값은 **계약 설명을 위한 예시이며 앱에 주입되지 않습니다.**

```json
{
  "sourceName": "허가받은 관측 공급원",
  "fetchedAt": "2026-11-10T09:00:00Z",
  "raids": [
    {
      "id": "stable-raid-occurrence-id",
      "gymName": "공급원이 실제 관측한 체육관 이름",
      "cityId": "seoul",
      "lat": 37.57,
      "lon": 126.97,
      "bossName": "자마젠타",
      "startsAt": "2026-11-10T09:05:00Z",
      "endsAt": "2026-11-10T09:30:00Z",
      "observedAt": "2026-11-10T08:59:00Z",
      "sourceUrl": "https://provider.example/public-observation"
    }
  ]
}
```

`id`는 개별 레이드의 안정 ID이며 체육관의 다른 레이드는 다른 ID를 사용합니다. `bossName`, `sourceUrl`만 생략하거나 null로 보낼 수 있습니다. 모든 시각은 초 단위 이상 ISO 8601이며 `Z` 또는 `+09:00` 같은 UTC 오프셋이 필요합니다. 도시 ID는 [cities.ts](../lib/cities.ts)에 등록된 24개 도시 중 하나입니다. 좌표는 숫자이고 위도 ±90, 경도 ±180 범위여야 합니다.

응답 최대 1 MiB, 레이드 최대 1,000개입니다. ID 160자, 체육관명 180자, 보스명 120자, 공급원명 120자 제한입니다. 역전된 시각·없는 날짜·24시간을 넘는 레이드·7일보다 먼 시작·미래로 60초를 초과한 관측은 거부합니다. 동일 ID는 더 최근 관측만 남깁니다. HTTPS 원문 링크에 인증 정보를 넣지 않습니다.

## 공개 API와 화면 상태

`status`는 다음과 같이 구분합니다.

| 상태 | 의미 |
| --- | --- |
| `unconfigured` | 서버에 공급원을 연결하지 않음 |
| `ready` | 표시할 수 있는 최근 관측이 있음 |
| `empty` | 공급원이 정상 연결되었으나 유효한 현재·예정 레이드가 없음 |
| `stale` | 공급원 갱신이나 관측이 10분 이상 오래되어 표시하지 않음 |
| `error` | 연결·인증·응답 형식·설정 오류. 빈 데이터로 정상 처리하지 않음 |

`fetchedAt`은 공급원 갱신시각, `checkedAt`은 우리 서버가 확인한 시각입니다. 둘을 같은 ‘최신 데이터 시각’으로 표시하지 않습니다. `discarded`는 잘못된 항목(`invalid`), 오래된 관측(`stale`), 종료된 항목(`ended`) 수를 제공합니다. 일부 항목만 잘못된 경우 나머지 유효 항목은 반환합니다. 오래된 공급원 자체를 거부한 경우 개별 항목을 검사하지 않으므로 이 수는 0일 수 있습니다.

각 레이드는 `status: "active" | "upcoming"`과 `expiresAt`을 포함합니다. 시작까지는 예정, `startsAt <= 현재 < endsAt`일 때만 진행 중입니다. 유효기한은 관측시각 + 10분과 실제 종료시각 중 빠른 값입니다. **클라이언트도 현재시각이 `expiresAt`이나 `endsAt`에 도달하면 즉시 제외**해야 합니다. 시작·종료가 지나면 서버에서 받은 상태 문자열을 그대로 유지하지 말고 원문 시각으로 다시 계산합니다. 실제 다음 레이드는 새 관측 없이 자동 생성하지 않습니다.

API는 `Cache-Control: no-store`, 공급원 요청은 8초 제한을 적용합니다. 권장 UI 재조회 간격은 30~60초입니다. 연결 실패 때 예전 레이드를 ‘진행 중’으로 돌려주는 복구 동작은 없습니다. 수동으로 기록한 체육관은 별도 출처로 표시하고 공급원 관측과 구분합니다.

공급원 범위가 전세계 전체라는 보장은 없습니다. `empty`는 공급원이 전달한 범위에서 항목이 없다는 뜻이며 전세계 레이드가 0개라는 뜻이 아닙니다. 현재는 같은 반경·면적·관측 범위를 보장할 수 없으므로 레이드 수를 전세계 밀집도 순위로 사용하지 않습니다.

검증: `node --test tests/live-raids.test.mjs`.

## 다른 사이트 데이터 연동

공개 페이지를 읽을 수 있다는 사실만으로 제3자 데이터의 자동 수집·재게시 허용을 확인했다고 취급하지 않습니다. 사이트별 이용 조건, robots.txt, 공개 API·내보내기 문서, 재사용 허용 범위와 호출 제한을 확인하고 서버 어댑터를 연결합니다. 로그인 세션·유료 접근·접근 제한을 우회하는 흐름은 구현하지 않습니다. 공급원이 정해지면 동일 지역을 짧은 간격으로 중복 조회하지 않도록 서버 캐시·중복 요청 합치기·실패 시 대기를 적용합니다.

2026-11-10에 확인한 화면 후보:

- [NYCPokeMap 레이드](https://www.nycpokemap.com/gym.html): 뉴욕의 체육관 레이드 페이지. 데이터 자동 수집·재게시 허용은 미확인.
- [SydneyPogoMap 레이드](https://www.sydneypogomap.com/gym.html): 시드니의 레이드 페이지. 동일하게 재사용 조건 미확인.
- [SGPokeMap 레이드](https://sgpokemap.com/gym.html): 싱가포르의 레이드 페이지. 동일하게 재사용 조건 미확인.
- [Pokémon GO 공식 지도](https://pokemongo.com/map): 확인 시 게임 계정 로그인이 필요. 인증 정보를 빌려 수집하지 않음.

현재 제품은 앞의 세 지역 지도로 이동하는 링크만 제공합니다. 이 페이지들을 자동 수집하거나 해당 데이터가 pokedoko 지도에 연결되었다고 표시하지 않습니다. 일정·보스의 ScrapedDuck 피드는 체육관별 관측 공급원과 구분합니다.
