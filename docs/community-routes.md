# 지가르데 셀 루트 커뮤니티

`/routes?city=seoul`의 공개 목록은 실제 Pokémon GO 게임 Route의 제보를 운영자가 검토해 게시하는 기능이다. 일반 포켓스톱 파밍 GPX는 대상이 아니다. 공개 Route 자체와 셀 지급 여부는 다르며, GPX를 내려받아도 게임에서 해당 Route를 선택하고 시작해야 한다. 셀 획득은 보장하지 않는다.

## 초기 데이터와 상태

2026-11-10 공개 GPX 자료를 다시 조사했지만, 실제 게임 Route 정체성과 원저작자의 재배포 허락을 함께 확인한 초기 파일은 0개였다. 목록을 채우기 위해 일반 파밍 GPX나 고토구 My Maps 안내선을 승인 자료로 넣지 않았다. 공개 목록이 비어 있으면 그대로 설명하며, 저장소 오류와 0개 상태도 구분한다.

원본 자료 조사에는 PogoMap, Campfire 익명 웹, 게임 공식 웹 지도, 고토구 공식 파트너 Route, 공개 GPX 저장소를 포함했다. 공개 소스 코드의 MIT/Apache 라이선스를 게임 데이터 라이선스로 취급하지 않는다.

- `original`: 제작자 등이 제공한 원본 경로라는 제보. 공개 후에도 ‘운영자 검토’이며 Pokémon GO의 공식 내보내기·인증을 뜻하지 않는다.
- `none`: 시작 위치·이름·거리 등만 확인한 루트. ‘전체 경로 미확보’, GPX 없음.
- `estimated`: 시작·끝 또는 안내를 기준으로 만든 추정 경로. 검토 후 공개해도 ‘추정 경로·검증 필요’를 유지한다.
- `reconstructed`: 이미지 등에서 복원한 경로. 검토 후에도 ‘복원 경로·검증 필요’를 유지한다.

원본 경로와 다른 길을 만드는 추정·복원 작업은 제보자가 방법과 근거를 설명해야 한다. 서버가 시작·끝만으로 GPX를 생성하지 않는다. GPX에는 저장된 전체 점만 원래 순서대로 기록하고 만들어 낸 시간·완료 정보는 넣지 않는다.

## 제보

로그인 없이 이름·도시·시작 이름과 좌표·게임 표시 거리·확인 날짜·공개 닉네임을 입력한다. 종료 위치와 GPX는 선택이다. GPX가 없으면 원본·추정·복원으로 분류하지 않고 `none`으로 접수한다.

원본 GPX를 올리면 브라우저에서 기존 GPX 파서를 이용해 연속된 트랙 한 개를 읽는다. 원본 파일을 외부 서버에서 URL로 가져오지 않는다. DTD·ENTITY, 다중 트랙, 비정상 XML을 거부한다. 파일은 1MiB, 전체 점은 2,000개, 서버의 실제 JSON 스트림은 192KiB로 제한한다. 원본 XML 대신 검증된 좌표를 D1에 저장한다.

제보자는 실제 게임 Route 확인과 해당 자료의 공개·GPX 재배포 허락을 각각 확인한다. 본인 제작, 제작자의 허락, 공개 라이선스 중 근거를 선택한다. 타인 제작·라이선스 자료는 HTTPS 출처와 20자 이상의 근거가 필요하다. 공개된 파일이라는 이유만으로 재배포 권리가 있다고 처리하지 않는다. 동의 체크 자체가 권리를 보증하거나 분쟁을 없애지는 않으므로 운영자가 별도 검토한다.

승인하면 닉네임·시작/종료 좌표·출처·권리 근거·설명 등이 공개된다. 실제 이름·연락처·집 주소 등 개인정보를 쓰지 않는다. 서버는 원래 IP·사용자 에이전트를 이 테이블에 기록하지 않으며 무작위 브라우저 키는 해시만 보관한다. 접수번호는 공개 게시 ID와 같지만 승인 전에는 그 번호로 조회하거나 다운로드할 수 없다.

## 수치 검증

검사는 자료 품질을 걸러내는 입력 기준이며 게임 승인 여부를 자동 입증하지 않는다.

- 유한한 위도 -90~90, 경도 -180~180, 순서 좌표 2~2,000개.
- 인접한 두 점이 500m를 넘으면 누락/도약으로 거부한다. 드문드문 저장한 정당한 경로도 이 기준에서 거부될 수 있으므로 보간해 통과시키지 말고 원본의 충분한 좌표를 확보한다.
- 계산 거리가 게임 표시 거리와 `100m 또는 표시 거리의 10% 중 큰 값`보다 많이 다르면 거부한다.
- 별도로 입력한 시작·끝과 GPX 끝점 차이는 100m 이내여야 한다.
- 입력 거리 한도는 100~100,000m다. 이것은 서비스 입력 한도이며 게임 Route 생성 규칙을 뜻하지 않는다.
- 시작은 선택한 대표 도시 중심에서 100km, 끝은 150km 이내로 제한한다. 도시 선택과 다른 국가의 좌표를 잘못 연결하는 사례를 줄이기 위한 범위다.
- 확인 날짜는 선택한 도시의 IANA 시간대 기준 오늘 또는 이전의 실제 달력 날짜여야 한다.
- 공개 상세/GPX 응답도 저장된 좌표를 다시 검사한다. 손상된 자료는 발행하지 않는다.
- 숫자 정밀도와 비연속 반복점을 보존한다. GPX 숫자는 지수 표기 없이 저장하며 경도 +180만 같은 위치인 -180으로 정규화한다.

## 공개/비공개와 저장

D1 `community_routes`에 처음에는 `pending`으로 접수한다. 일반 방문자에게 목록·상세·GPX를 제공하는 API는 `approved` 및 게임/권리 검토 플래그가 모두 설정된 행만 읽는다. `rejected`, `removed`, `pending`은 상세·GPX404다. 미승인 목록 조회·승인·거절을 위한 공개 HTTP 관리 API는 없다.

원본 이용 허락이 있는 자료도 게임 내 Route 정체성을 별도로 확인한다. 이름 하나만으로 자동 매칭하지 않는다. 현재 자동 수집기나 추정 경로 자동 생성기는 없다. 개인 GPX/localStorage 방문 계획 기능은 유지하며 커뮤니티 목록과 구분한다.

같은 브라우저의 같은 대기 자료 재시도는 접수번호를 유지한다. 다른 제보자의 미공개 ID·내용은 알려주지 않는다. 신규 제보는 브라우저 키당 시간당3개, 전체 하루1,000개, 검토 대기500개로 제한한다. 이는 기본 과다 접수 완화이며 모든 봇을 구분하는 인증 수단은 아니다. 만료한 접수 제한 카운터는 기존 정리 작업에서 최대5,000개씩 삭제한다.

## 운영자 검토

기존 Cloudflare Wrangler 로그인과 D1 권한을 쓴다. 관리자 비밀번호를 브라우저에 넣거나 별도 공개 관리자 로그인 API를 만들지 않았다. 기본 운영 DB는 `pokedoko-growth`이며 다른 배포의 DB를 볼 때 `--database`로 정확히 지정한다.

```sh
npm run routes:review -- list
npm run routes:review -- list --city seoul
npm run routes:review -- show 접수ID
npm run routes:review -- export 접수ID --output /private/tmp/route-review.json
```

`list`는 최대50개, `show`는 비공개 제보와 좌표 개수·처음/마지막 점을 보여 준다. `export`는 검토용 전체 좌표 JSON을 새 파일에 저장하며 기존 파일을 덮지 않는다. 비공개 제보·검토 파일을 GitHub에 넣지 않는다.

아래 자료를 확인한 뒤에만 승인한다.

1. 실제 게임 Route의 이름·도시·시작/끝·방향·거리가 제보 자료와 일치하는가.
2. 원저작자의 제작/허락 또는 실제 자료에 적용되는 라이선스가 공개 GPX 제공을 허용하는가.
3. 추정·복원이면 그 분류와 설명이 정확하고 원본 경로처럼 표시되지 않는가.
4. 닉네임·설명·출처·권리 근거에 공개하면 안 되는 개인정보가 없는가.

```sh
npm run routes:review -- approve 접수ID --rights-checked --game-route-checked --note "게임 Route 시작·끝·거리와 제작자의 재배포 허락을 확인한 근거"
npm run routes:review -- reject 접수ID --note "게임 Route 원본 경로 근거가 부족해 보류"
npm run routes:review -- remove 접수ID --note "제작자의 공개 중단 요청으로 게시 중단"
```

위 명령의 `접수ID`는 실제 UUID로 바꾼다. 공개 데이터는 승인 명령 실행 후 게시된다. 두 확인 플래그와 검토 근거가 없으면 승인할 수 없고, CLI도 제출 규칙과 좌표를 다시 검사한다. `none`은 목록만 게시하고 다운로드를 제공하지 않는다. 추정·복원 GPX 파일명과 내부 메타데이터에도 분류를 기록한다. 공개 후 문제 제보는 기존 사이트 의견 보내기 또는 원출처를 통해 확인해 `remove`로 중단한다. 이미 내려받은 파일을 회수하는 기능은 아니다.

로컬 QA는 별도 D1 상태 디렉터리를 사용하고 `--local --config /절대경로/wrangler.json`을 지정한다. 원격 데이터와 혼동하지 않는다. SQL/Drizzle schema는 `0001_clumsy_red_hulk.sql`로 추가되며 접수 때 테이블을 생성하지 않는다.
