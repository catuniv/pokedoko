# 레이드 방문 경로와 GPX

선택한 지역 중심에서 실제 수집된 체육관을 방문하는 순서를 계산한다. 같은 도시와 선택 반경 안에 있는 현재 조건의 레이드만 입력한다. 도로·횡단보도·출입 가능 여부를 확인하는 길 찾기 서비스가 아니며 모든 거리와 이동 시간은 지구 구면의 직선거리 추정이다. 경로가 최적이라고 주장하지 않는다.

## 계산과 유효성

`buildRaidRoute(raids, region, now, options)`의 기본값은 이동속도 4.5km/h, 체육관당 5분, 최대 10곳, 총 60분이다. 허용 범위는 각각 1~30km/h, 1~30분, 2~30곳, 15~180분이다. 설정값을 바꿔도 실제 이동 가능성을 보장하지 않는다.

- 생성 시각에 자료가 유효하고 종료까지 5분 이상 남은 레이드만 쓴다. Max Battle·다이맥스 자료와 잘못된 좌표·시각은 제외한다.
- 이동 후 시작 전이면 실제 시작 시각까지 기다린다. 체류 완료가 종료 1분 전보다 늦거나 총 시간 한도를 넘으면 방문 후보에서 제외한다.
- 같은 식별자 또는 같은 도시의 좌표 6자리 기준으로 중복된 체육관을 한 번만 사용한다. 결과의 실제 좌표는 반올림하지 않는다.
- 유효 후보가 500개를 넘으면 가까운 후보와 종료가 빠른 후보를 섞어 최대 500개로 제한한다. `candidateCount`는 제한 전, `cappedCandidateCount`는 실제 비교 수다.
- 최대 12개의 가까운 순서·마감 우선 탐색을 비교한다. 방문 수가 많고, 예상 소요 시간과 직선거리가 짧은 결과를 고른다. 미선택 항목은 후보 상한·중복·시간 부족 등의 이유별로 반환한다.

`validUntil`은 선택한 원문 자료 중 가장 빠른 유효기간이다. 그 시각 이후 재조회해야 한다는 의미이며 방문 완료 시각이 아니다. 미래 레이드의 예상 도착 시각이 자료 유효기간보다 늦을 수 있으므로 실제 방문 전 최신 상황을 다시 확인해야 한다.

`isRaidRouteCurrent(route, raids, now)`는 경유지가 2곳 이상이고 생성 후 2분 미만인 계획만 허용한다. 원본 자료의 유효기간이 지나거나 최신 자료에서 선택한 레이드가 없어지거나 도시·좌표·보스·폼·등급·시작/종료가 달라지면 다시 생성해야 한다. 시각이 흐른 만큼 예상 출발을 늦춰도 종료 1분 전 완료 조건을 만족해야 한다. 설정 변경 여부와 최신 입력 비교는 화면에서도 확인한다.

## 내보내기

- `raidRouteToCoordinates(route)`: 선택 중심과 방문 순서의 `위도,경도`를 줄바꿈으로 연결한다. 첫 체육관이 중심과 같은 좌표면 한 줄만 쓴다.
- `raidRouteToGpx(route)`: [Topografix GPX 1.1 명세](https://www.topografix.com/GPX/1/1/)에 맞는 `rte`와 `trk`를 함께 만든다. 두 형식 모두 같은 실제 좌표를 같은 순서로 사용하며 도로 중간점을 만들어 넣지 않는다.
- GPX의 `<time>`은 메타데이터의 생성 시각에만 쓴다. 경유지나 트랙 지점에는 실제 활동처럼 보일 수 있는 기록 시각을 넣지 않는다.
- 좌표의 숫자 정밀도를 유지하며 작은 수의 지수 표기는 소수로 펼친다. GPX 경도 범위는 -180 이상 180 미만이므로 원본 경도 180은 같은 위치인 -180으로만 바꾼다. 좌표 텍스트에는 원래 숫자를 유지한다.
- XML 특수문자는 이스케이프하고 XML 1.0에서 허용하지 않는 제어문자는 제거한다. 파일명은 ASCII다.
- 체육관이 2곳 미만이면 내보내기를 거부한다. 내보내기 직전에 최신 자료와 `isRaidRouteCurrent`를 확인해야 하며, 오래된 파일 자체가 자동 갱신되지는 않는다.

시간표와 수집 자료는 계속 바뀐다. 파일은 생성 시점의 방문 계획이며 실제 진행·모집 인원이나 이동 기록을 증명하지 않는다.
