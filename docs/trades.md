# 포켓몬 교환 상대 찾기

`/trades`는 줄 포켓몬과 원하는 포켓몬을 등록해 상대를 찾는 게시판이다. 실제 교환은 당사자가 Pokémon GO에서 진행한다. 게임 계정·인벤토리·우정 단계·별의모래·교환 실행 API를 연동하지 않으며 보유 여부나 교환 성립을 인증하지 않는다. 현금·계정 거래 게시판으로 제공하지 않는다.

## 모집과 공개

- 포켓몬은 기존 도감의 한국어·영어 이름 또는 번호로 찾아 제공/희망 각각1마리를 고른다. 색이 다른 모습 여부와 형태 설명을 별도로 적는다. 형태는 사용자 설명이며 게임에서 가능한 조합인지 자동으로 검증하지 않는다.
- 대면 교환 모집과 리모트 교환 준비를 구분한다. 지역은 기존 지원 도시 중 선택한다. 리모트 선택이 즉시 원격 교환 가능함을 뜻하지 않는다.
- 공개 닉네임과 트레이너 코드(숫자12자리), Discord 사용자 이름, 카카오 공개 오픈채팅 주소 중 연락 방법을 제출한다. 승인 후 연락 방법이 공개됨에 동의해야 한다. 실제 이름·전화번호·집 주소·게임 비밀번호는 받지 않는다.
- 처음에는 `pending`으로 저장하고 운영자가 내용을 검토한 뒤 게시한다. 승인 전에는 글 ID를 알아도 외부에서 상세·연락처를 조회할 수 없다. 공개 목록에는 연락처가 없고 승인된 모집 글의 상세에만 포함한다.
- 모집 기간은1·3·7일이다. 만료 시각부터 목록·공개 상세에서 즉시 숨긴다. 마감·거절·공개 중단도 목록·공개 상세에 표시하지 않는다.
- 최초 목록은0개이며 실제 이용자의 모집 글을 검토해 채운다. 개발용 예시 글을 운영 DB에 넣지 않는다.

## 현재 공식 교환 안내

확인일2026-11-10. 이벤트와 게임 업데이트에 따라 조건이 달라질 수 있어 상세 조건과 비용은 게임·공식 안내에서 확인한다.

- [일반 교환 공식 도움말](https://scopelyexplore.helpshift.com/hc/en/5-pokemon-go/faq/1143-trading-pokemon/): 대면 교환은 가까이 있어야 하며 레벨·교환 대상·별의모래 등의 조건이 있다. 확인한 문서에 없는 정확한 거리 수치나 모든 특별 교환의 일일 횟수를 고정 안내하지 않는다.
- [리모트 교환 도움말](https://scopelyexplore.helpshift.com/hc/en/5-pokemon-go/faq/861-trading-remotely/), [공식 한국어 공지](https://pokemongo.com/ko/news/pgo-remote-trade-2025): 포에버 프렌드·프렌드 포인트와 리모트 교환 기회 조건이 있다. 즉시 아무 상대와 교환할 수 있는 기능이 아니다.
- 최근 포획 포켓몬·이미 교환한 포켓몬·특정 상태/대상 등은 리모트 교환에 제한이 있다. 게시판에 모집 글을 올렸다는 사실만으로 실제 교환 가능하다고 표시하지 않는다.

## 로그인 없는 작성자 관리

브라우저가 글마다32바이트의 무작위 관리 키를 만든다. 서버에는 도메인 구분 접두어와 함께 SHA-256 해시만 저장한다. 원래 관리 키·브라우저 식별자·해시는 공개 목록/상세나 이용 통계에 넣지 않는다. 원래 IP·사용자 에이전트를 이 테이블에 저장하지 않는다.

관리 정보는 접수 요청 **이전**에 글마다 별도 브라우저 저장 항목에 기록하고 읽기 확인을 한다. 저장소가 차단되면 새 글을 접수하지 않고 안내하며 공개 목록 조회는 계속 가능하다. 접수 응답이 유실돼도 같은 기기에서 관리 키로 접수 결과를 다시 확인한다. 확인되지 않은 작성 기록은 자동 폐기하지 않는다. 여러 탭이 각각 글을 작성해도 공유 배열을 덮어쓰지 않도록 하고 저장 변경을 다른 탭의 관리 목록에 반영한다.

신규 작성은 기기의 관리 기록30개를 기준으로 제한한다. 경합 등으로 이미 그 이상인 기록도 임의로 자르거나 관리 키를 폐기하지 않는다. 기존 배열 형식의 관리 기록은 모든 개별 기록의 저장에 성공한 뒤에만 이전 원본을 제거한다. 작성자는 ‘내 모집 글’에서 상태를 확인하고 마감·삭제한다. API는 글 ID와 올바른 관리 키가 모두 있어야 동작하며 원래 키를 URL에 넣지 않는다. 관리 키는 해당 글의 관리 권한이므로 다른 사람에게 공유하지 않는다.

동일 관리 키의 접수 재시도는 기존 글 ID를 반환해 중복 접수를 줄인다. 수정 기능은 없으며 내용을 바꾸려면 기존 글을 마감/삭제하고 새 글을 등록한다. 게임 계정 로그인과 연결되지 않아 다른 기기에서 자동 복구되지 않는다. 본인이 삭제하면 글 행을 실제로 삭제하며, 마감은 모집 상태만 바꾼다.

신규 글은 브라우저 키당 시간당3개, 전체 하루1,000개, 현재 유효한 검토 대기500개로 제한한다. 이는 기본 과다 접수 완화이며 모든 봇이나 실제 사람을 인증하는 수단이 아니다. 만료 후30일을 지난 글과 만료된 제한 카운터는 기존 정리 작업에서 테이블별 최대5,000개씩 삭제한다.

## 운영자 검토

기존 Cloudflare Wrangler 로그인과 D1 권한을 쓴다. 별도의 공개 HTTP 승인 API나 관리자 비밀번호는 추가하지 않았다.

```sh
npm run trades:review -- list
npm run trades:review -- list --city seoul
npm run trades:review -- show 모집글ID
npm run trades:review -- approve 모집글ID --checked --note "포켓몬·모집 설명과 연락 방법 공개 동의를 확인한 근거"
npm run trades:review -- reject 모집글ID --note "모집 규칙에 맞지 않아 공개 보류"
npm run trades:review -- remove 모집글ID --note "사용자의 공개 중단 요청을 확인해 중단"
```

ID는 실제 UUID로 바꾼다. `show`에는 미공개 연락 방법이 있으므로 출력물을 GitHub 등에 올리지 않는다. CLI도 소유 관리 키나 그 해시를 출력하지 않는다. 승인 전 닉네임·모집 내용·연락 방법 공개 동의·금전/계정 거래나 부적절한 개인정보 포함 여부를 확인한다. 관리자가 승인해도 게임 계정이나 보유 포켓몬을 인증한 것은 아니다.

기본 DB는 `pokedoko-growth`다. 로컬 QA는 `--local --database site-creator-d1 --config /절대경로/wrangler.json --persist-to /절대경로/qa-state`로 별도 DB를 지정한다. `0002_sticky_tigra.sql`은 새 테이블·입력 제한 트리거와 Route의 nullable metadata만 추가한다. 기존 Route·일정·통계 자료를 덮어쓰지 않는다.
