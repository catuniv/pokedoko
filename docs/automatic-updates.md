# 일정 자동 갱신 운영

## 평상시 갱신

`/api/feed`는 서버에서 LeekDuck/ScrapedDuck의 공개 이벤트·레이드 피드를 확인합니다. 원문에 새 일정이 등록되면 코드 재배포 없이 반영됩니다. 현재는 공식 공지를 직접 전수 해석하는 수집기가 아니며, 공식 확인 목록은 날짜가 확정된 보완 자료입니다. 미발표 일정이나 다음 해 날짜를 반복 규칙으로 만들지 않습니다.

일정 공유 캐시는 R2의 `pokedoko/feeds/public-schedule-v1.json`에 저장합니다. 신선한 원문과 저장본은 최대5분 동안 재사용하며, 만료 후 고정 원본에서 다시 가져옵니다. 사이트를 보고 있을 때는5분마다, 모바일에서 화면으로 돌아오면 즉시 조회합니다. CDN/SWR 캐시를 겹치지 않도록 `/api/feed`는 `Cache-Control: no-store`입니다.

공개 GET은 임의 일정을 입력받지 않습니다. 고정한 공공소스를 읽어 검증한 정상 결과만 공유 캐시에 저장하므로, 사이트를 닫아 둔 동안에도 연결된 예약 작업이 같은 GET을 호출해 자료를 갱신할 수 있습니다. 저장용 비밀키나 공개 데이터 수정 POST는 없습니다.

## 기간과 장애 처리

- 날짜가 확인된 보스는 선택 도시의 현지 시작·종료 시각으로 현재/예정을 구분합니다. 종료 시점부터 현재 목록에서 제외합니다.
- 기간을 모르는 보스는 ‘기간 미확인’으로 분리하고 현재 등장한다고 보장하지 않습니다.
- 화이트큐레무와 블랙큐레무는 도감 번호가 같아도 폼과 날짜를 구분합니다. 주말 전체 행사에 두 보스를 동시에 현재 등장으로 섞지 않습니다.
- 레이드아워는 다음 확정 일정으로 넘어가고, 없으면 확정 일정이 없다고 표시합니다. 마지막 과거 일정을 미래처럼 되돌리지 않습니다.
- 오류가 나면 마지막 정상 저장본의 원문 시각을 보존합니다. 실패·부분 자료로 정상 저장본을 덮어쓰지 않습니다.
- 미완료 일정 요청은9초 lease로 교체하고 늦은 이전 요청이 새 캐시를 덮지 못하게 합니다.

## 예약 작업에서 확인할 공개 인터페이스

사이트: `https://pokedoko.adorablecompass.chatgpt.site`

1. 익명 GET `/api/feed`를 호출합니다. 이 고정 원본 read-through가 갱신 동작이며 재배포가 필요하지 않습니다.
2. HTTP200, `events`/`bosses` 배열, `fetchedAt`/`error`를 확인합니다. 정상 시 `X-Pokedoko-Feed-Storage: ready`를 확인합니다.
3. 다시 GET하여 `X-Pokedoko-Feed-Cache: r2` 및 같은 `X-Pokedoko-Feed-Stored-At`으로 저장 결과를 확인합니다. 저장 시각과 원문 시각은 구분합니다.
4. 일시 오류는 한 번 더 확인하고, 반복 실패만 보고합니다. 오래된 자료의 시각을 현재로 바꾸거나 일정을 추정하지 않습니다.

예약 작업은 같은 동작의 간결한 GET `/api/feed?status=1`을 사용할 수 있습니다. JSON의 `ok`, `storage`, `cache`, `storedAt`, `fetchedAt`, 일정/보스 개수로 갱신과 저장본 재조회를 확인합니다. 이 옵션은 응답 크기만 줄이며 소스·일정 입력을 받지 않습니다.

공개 범위·사용자 데이터·소스코드·배포 설정은 예약 작업이 변경하지 않습니다. 공유 캐시는 공급원 중단을 없애지는 못하므로 오류 상태와 마지막 확인 시각을 유지합니다.
